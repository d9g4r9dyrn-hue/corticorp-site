# CortiCorp Site Hub

Central project registry and content-management hub for corticorp.com. Tracks all
CortiCorp Claude projects (plugins, tools, finders) and generates website content
from them. Deployed to corticorp.com (see CNAME) via GitHub Pages.

## Stack
- TypeScript (ES2020, strict, ESM), compiled with `tsc` to `dist/`.
- Static site: hand-written HTML at root (`index.html`, `journal.html`, `projects.html`).
- `glob` is the only runtime dependency (used by the project scanner).

## Commands
- `npm install` — install deps
- `npm run build` — `tsc` compile src/ -> dist/
- `npm run dev` — `tsc --watch`
- `npm run scan` — auto-discover projects and update the registry (`node dist/index.js`)
- `npm run registry:list` — print all registered projects
- `npm run registry:update` — rewrite the registry

Note: run `npm run build` before any `registry:*`/`scan` script — they execute the
compiled JS in `dist/`, not the TS source.

## Layout
- **src/types/Project.ts** — Project/Plugin interfaces (the registry schema).
- **src/scanner/ProjectScanner.ts** — auto-discovery. `KNOWN_PROJECTS` is the list of
  tracked project folders; add a folder name here to track a new project.
- **src/registry/** — RegistryManager + list/update query tools.
- **src/index.ts** — entry point (the `scan` script).
- **projects/** — registry output + per-project metadata. `projects/registry.json` is
  gitignored (generated by scan).
- **dist/** — compiled output (gitignored).
- HTML pages at root are the actual published site.

## Projects tracked
compressor_plugin (CortComp VST3), CortSynth, apartment-finder, catfish-finder.
Sibling projects live under `../` (Desktop/corticorp/…). Paths in the registry are
relative to the corticorp root via `pathFromCortiCorp`.

## Workflow for generating site content
1. Register a project: add its folder to `KNOWN_PROJECTS` in `ProjectScanner.ts`.
2. `npm run build && npm run scan` to refresh the registry.
3. To publish, analyze a project's source + its CLAUDE.md and generate HTML for the
   relevant page (projects.html / journal.html).

## Conventions
- Registry is the source of truth for what appears on the site; don't hand-edit the
  generated `registry.json` — change the scanner or source metadata and re-scan.
- Keep `dist/` out of commits (gitignored); build is reproducible from `src/`.

## Sharing project pages
Every `projects/<slug>/index.html` details page carries:
- The social preview tags (canonical, `og:*`, `twitter:card summary_large_image`) pointing at
  `projects/<slug>/img/share.jpg`, a 1200x630 card. LinkedIn and Facebook don't show SVG.
- `<div data-share></div>` at the end of the hero plus `<script src="/js/share.js" defer>`,
  which renders the LinkedIn / Facebook / X / copy-link row (and the phone's share sheet).

Cards are generated, not hand-made: add or edit the project in `scripts/share-cards/cards.json`
(`logo` for a centered emblem, `shot` for a framed screenshot), then run
`node scripts/share-cards/render.cjs [slug]` (needs Playwright; `NODE_PATH` can point at
`../news/node_modules`). After changing a live card, re-scrape it in LinkedIn Post Inspector
and the Facebook Sharing Debugger, which otherwise keep the old preview.
